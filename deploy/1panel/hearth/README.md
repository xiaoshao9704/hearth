## 产品介绍

Hearth 是自建的语音 / 投屏 / OBS 推流 / 聊天房间——几个朋友的私人客厅：开一间频道，几个人进来说话，把画面投上去。

一个容器就是全部：API、媒体内核、推流入口、前端都在里面，没有 redis、没有第二个服务、不需要另装媒体服务器。

## 主要功能

- **语音**：SFU 转发的多人语音，降噪与回声消除、按键说话、挂机自动静音，同账号多设备同时在房
- **投屏与推流**：1080p60 高码率投屏并带系统声音，摄像头同一条线；OBS 走标准 WHIP 直推不装插件，服务端不转码原样透传，HEVC / AV1 直通
- **聊天**：带 @、回复、表情反应与文件直传，历史由服务端落库回放
- **账号与权限**：通行密钥（Passkey）登录，注册默认邀请制，首个账号自动成为超级管理员
- **自带 https**：一个端口同时收 http 与 https，证书三选一（自签根证书 / 外部证书文件 / 后台上传）

## 安装后

在 1Panel 的「容器 → 终端」里，或用 SSH 执行，创建第一个账号（自动成为超级管理员）：

```bash
docker exec -it 1Panel-hearth-<后缀> /app/hearth adduser alice change-me
```

容器名以应用列表里显示的为准。然后打开 `http://<主机>:<Web 端口>`。

**局域网里其它设备第一次要打开 `https://<主机>:<Web 端口>/ca` 装一次根证书**（用 http 也能打开），
装完把地址换成 https 打开，麦克风、投屏、通知这些要安全上下文的权限浏览器才给。

## 端口

| 端口 | 用途 |
|---|---|
| Web 端口（默认 8080/tcp） | Web / API / 信令 / WHIP，同端口默认也收 https |
| 47720/udp | 媒体端口（语音与投屏共用），**必须**在防火墙 / 安全组放行 |
| 47720/tcp | ICE-TCP 兜底，只在 UDP 被中间设备接管的网络才用得上 |

媒体端口固定 47720，不做成表单项：进程内的媒体内核把自己监听的 UDP 端口写进 ICE 候选，
宿主端口与容器端口不同号会让候选指向一个连不通的端口。真要换号，得同时改 compose 的端口映射与
Hearth 管理后台的「舞台 → 媒体 UDP 端口」，两处一致才行。
